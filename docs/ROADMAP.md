# Roadmap

목표일은 2026-08-15이며 일정이 촘촘하다. 각 기간의 다음 단계 진입 조건을 충족하지 못하면 아래 제거 후보부터 범위를 줄이고, 핵심 두 시나리오와 업무 규칙 테스트는 유지한다.

## 2026-07-30 ~ 2026-07-31 — 기획과 준비

- 구현 기능: 기획 문서, 개발 규칙, 후보 구조, 환경설정 방향, Supabase 개발 프로젝트 준비
- 완료 조건: 문서 일관성 확인, 실제 비밀값 미기록, 개발 DB 준비 기준 확정
- 테스트 항목: 문서 파일·링크·핵심 용어와 범위 점검
- 배울 개념: 계층 분리, 환경변수, PostgreSQL 프로젝트 분리
- 위험 요소: 문서 범위가 구현보다 커지는 것
- 지연 시 제거: README 시각 장식과 부가 예시
- 다음 단계 진입 조건: 결정되지 않은 핵심 정책이 `DECISIONS.md`에 정리됨

## 2026-08-01 ~ 2026-08-03 — 공통 환경과 기준 데이터

- 구현 기능: Backend/Frontend 기본 환경, DB 연결, Alembic, 직원·부서·역할 전환, 대시보드, Seed
- 완료 조건: 샘플 직원 전환과 DB 저장, 멱등 Seed
- 테스트 항목: Health, DB 세션, 직원/부서, 권한 조회, Seed 재실행
- 배울 개념: Python 모듈, FastAPI 의존성, Pydantic 모델, Session, PK/FK/Unique
- 위험 요소: 두 프레임워크와 원격 DB를 동시에 처음 설정
- 지연 시 제거: 대시보드 통계 세분화
- 다음 단계 진입 조건: 공통 사용자 컨텍스트와 migration이 안정적으로 동작

## 2026-08-04 ~ 2026-08-06 — 전자결재

- 구현 기능: 문서 작성, 상신, 승인, 반려, 이력, 상태 전환
- 완료 조건: 자기 결재와 완료 문서 재처리 차단, 알림 생성
- 테스트 항목: DRAFT→PENDING, PENDING→APPROVED/REJECTED, DRAFT→CANCELLED, 권한·트랜잭션
- 배울 개념: Enum, Service, 예외, transaction, 상태 머신
- 위험 요소: 범용 결재 모델을 과도하게 추상화
- 지연 시 제거: 결재 목록 고급 필터
- 다음 단계 진입 조건: 두 업무가 같은 결재 API/서비스를 재사용 가능

## 2026-08-07 ~ 2026-08-09 — ATS Lite

- 구현 기능: 채용 요청·결재, 승인 후 공고, 지원자, 단계 변경
- 완료 조건: 미승인 요청 공고 생성 차단과 대표 흐름 완료
- 테스트 항목: 역할, 공고 중복 생성, 지원 단계 유효성
- 배울 개념: 일대일·일대다 관계, 명령형 API, 서비스 조합
- 위험 요소: ATS 상세 기능 욕심으로 일정 초과
- 지연 시 제거: 공고 검색·필터, 지원자 부가 필드
- 다음 단계 진입 조건: AI 없이도 채용 핵심 데이터 흐름 동작

## 2026-08-10 ~ 2026-08-12 — CRM·견적 Lite

- 구현 기능: 고객, 상품, 기회, 견적, 할인 기준·결재, 승인 후 확정
- 완료 조건: 서버 재계산과 10% 경계 분기, 미승인 확정 차단
- 테스트 항목: Decimal 계산, 10%/10% 초과, 결재 연동, rollback
- 배울 개념: Decimal/NUMERIC, 집계, 설정값, 복합 트랜잭션
- 위험 요소: 금액·상태 규칙과 UI를 3일 안에 함께 구현
- 지연 시 제거: 영업기회 상태의 부가 단계, 상품 관리 편집
- 다음 단계 진입 조건: AI 없이 영업 시나리오의 승인·확정 완료

## 2026-08-13 — 공통 AI

- 구현 기능: MockAIProvider, 실제 Provider 인터페이스, 7개 요약·초안 기능
- 완료 조건: 키 없이 Mock 동작, 기록·수정·실패 fallback
- 테스트 항목: Provider 선택, 성공/실패 기록, 업무 상태 미변경
- 배울 개념: Protocol/ABC, 의존성 역전, timeout, 구조화 출력
- 위험 요소: 실제 Provider 연동과 프롬프트 품질에 시간 소모
- 지연 시 제거: 실제 LLM 구현체(인터페이스만 유지), 출력 형식 고도화
- 다음 단계 진입 조건: 두 시나리오에서 Mock 결과 생성·수정 가능

## 2026-08-14 — 통합 안정화

- 구현 기능: 통합 테스트, 오류 수정, Seed·README·UPDATELOG·시연 데이터 정리
- 완료 조건: 핵심 테스트 통과와 문서-구현 일치
- 테스트 항목: 두 E2E 흐름, 권한 위반, 실패 fallback, Seed 재실행
- 배울 개념: 회귀 테스트, fixture, 오류 분류
- 위험 요소: 통합 시 늦게 발견되는 상태·FK 불일치
- 지연 시 제거: 비핵심 UI polish와 부가 통계
- 다음 단계 진입 조건: 체크리스트에 핵심 오류가 없음

## 2026-08-15 — 시연과 버퍼

- 구현 기능: 채용·영업 시연, 체크리스트, 스크린샷/영상, 버퍼
- 완료 조건: 초기화된 시연 데이터로 두 흐름 재현
- 테스트 항목: 시연 리허설과 복구 절차
- 배울 개념: 기술 설명, 데모 스크립트, 한계 공개
- 위험 요소: 원격 DB/네트워크와 당일 수정
- 지연 시 제거: 실제 LLM 시연, 영상 편집, 장식성 화면
- 다음 단계 진입 조건: 프로토타입 종료 회고 후 확장 범위 승인

## 지연 시 전체 우선순위

유지: 전자결재 규칙, 승인 기반 공고, 할인 승인 기반 확정, Mock AI, 핵심 테스트.  
우선 제거: 실제 LLM 구현체 → 부가 검색/필터 → 대시보드 통계 → UI polish → 부가 ATS/CRM 필드. 전체 일정은 임의로 변경하지 않는다.
