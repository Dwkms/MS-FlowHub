# MS FlowHub Project Specification

## 기본 정보

- 프로젝트명: MS FlowHub
- 가상 회사명: MS
- 목표일: 2026-08-15
- 성격: 기업 업무 흐름을 축소 구현하는 취업 포트폴리오 프로젝트
- 목적: 전자결재를 중심으로 채용과 영업·견적 업무를 연결하고 반복 문서 작업을 생성형 AI로 보조한다.

## 기획 배경과 해결 문제

부서별 도구가 분리되면 요청 정보가 반복 입력되고 승인 상태와 후속 업무의 연결이 끊긴다. MS FlowHub는 공통 직원·부서·역할·알림 데이터와 전자결재 엔진을 공유하여 채용 요청에서 공고 생성까지, 견적 할인 요청에서 확정까지 추적한다. 요약과 초안 작성은 AI가 돕되 사람의 판단과 수정을 전제로 한다.

## 사용자 역할

일반 직원, 부서장, 인사 담당자, 영업사원, 영업팀장, 관리자. 프로토타입은 회원가입·로그인 대신 샘플 직원을 선택한다. FastAPI 서비스가 직원과 역할을 다시 조회해 권한을 판단한다.

## 모듈 구성

1. 전자결재: 공통 핵심 엔진, 단일 결재자, 상태 전환과 이력
2. ATS Lite: 승인된 채용 요청 기반 공고와 지원자 대표 흐름
3. CRM·견적 Lite: 고객·기회·상품·견적과 할인 결재 대표 흐름
4. 공통 AI 서비스: Provider 추상화, 생성 기록, 사용자 수정 결과

모듈은 분리하지만 공통 사용자, 부서, 권한, 알림, 결재 데이터를 공유한다. 전자결재는 상대적으로 깊게, ATS/CRM은 시연에 필요한 수준으로 구현한다.

## 프로토타입 범위

- 직원·부서·역할 전환, 대시보드, 접근 가능 모듈 표시
- 전자결재 작성·상신·승인·반려·의견·상태·이력·알림
- 승인된 채용 요청에서 공고 생성, 지원자와 단계 관리
- 고객·기회·상품·견적, 서버 금액 계산, 10% 초과 할인 결재
- MockAIProvider와 실제 LLM Provider 인터페이스, 7개 AI 기능
- Supabase PostgreSQL, Alembic, Seed, 오류 처리, 핵심 테스트

## 프로토타입 제외 범위

실제 인증과 Supabase Auth, 운영급 권한, 실제 이메일 발송, PDF 분석, OCR, RAG, 벡터 DB, n8n, 다단계 결재, WebSocket 알림, 실제 개인정보·기밀, Docker, 모바일 앱, 완전한 ERP/CRM/ATS, 자동 채용 결정, 실제 견적 이메일 발송.

## 주요 업무 정책

- 작성자와 결재자는 달라야 한다. 자기 결재는 프로토타입에서 금지한다.
- 결재는 허용된 상태 전환으로만 변경하며 처리 완료 문서는 재처리할 수 없다.
- 승인되지 않은 채용 요청은 공고로 만들 수 없다.
- 할인율이 10% 이하인 견적은 서버 재계산 후 결재 없이 확정할 수 있다.
- 10%를 초과한 견적은 승인 전 확정할 수 없다. 기준은 공통 설정으로 관리한다.
- AI는 승인·반려·채용 결과·견적 확정·실제 발송을 결정하거나 실행하지 않는다.

## 성공 기준과 완료 기준

채용 및 영업 시나리오를 샘플 사용자 선택부터 AI 결과 수정까지 처음부터 끝까지 시연하고, 데이터가 Supabase PostgreSQL에 저장되어야 한다. 프론트엔드는 FastAPI만 호출하며 Seed는 멱등적이어야 한다. 금지된 상태 전환이 차단되고 핵심 Backend 테스트가 통과하며 README/UPDATELOG가 실제 상태와 일치해야 한다.

## 장기 목표와 확장 가능성

프로토타입 이후 실제 인증, 다단계 결재, 강화된 권한·감사, 이메일 연동, 운영 DB 분리, 관측성과 배포 자동화를 단계적으로 도입한다. 현재 결과물을 실제 기업용 완제품으로 과장하지 않는다.
